# 2026-10-10

## viewTable 块改用 react-data-grid + 删除手写事件隔离层（关键转折）

用户反馈 v3 仍然「不能编辑」且质疑手写。深挖源码后推翻了此前诊断：

- **prosemirror-view 的 `eventBelongsToView`**（dist/index.cjs 约 2978 行）：事件目标向上走到 `view.dom`，途中任何 nodeView 的 `pmViewDesc.stopEvent(event)` 返回 true → PM 跳过该事件。
- **BlockNote 对 `content:'none'` 块的内置 stopEvent 对所有事件恒返回 true**（`@blocknote/core` defaultBlocks dist 中：`stopEvent = (n) => (n.type === "mousedown" && setTimeout(() => t.view.dom.blur(), 10), !0)`），mousedown 时还会主动 blur 编辑器。
- 结论：**ProseMirror 从来就看不见 content:'none' 块里的事件**，之前手写的 `useIsolatedBlockEvents` 是画蛇添足，反而把块内 React 冒泡阶段 handler（React 委托挂 app root，事件在块根被 stopPropagation 拦截后到不了 root）全杀了——这才是「不能编辑」的真正根因。sheet/思维导图块没加隔离也能编辑，旁证一致。
- 教训：块内要拦 PM 事件时先确认 BlockNote nodeView 已内置 stopEvent；React 委托机制下，块根原生 stopPropagation 会连带杀死 React bubble handler（capture handler 不受影响）。

## 用 Playwright 复现并真正修复编辑 bug（RDG 三个坑）

盲改两轮用户都说不行后，写临时 Playwright spec（fixture vault harness）在浏览器里真实操作，才定位到 RDG beta.61 的三个坑：

1. **列必须有 `renderEditCell` 才算可编辑**：`isCellEditableUtil = column.renderEditCell != null && editable !== false`——光设 `editable: true` 完全无效（d.ts 注释过时）。文本/数字/url 列都要配 renderEditCell。
2. **`onRowChange(row)` 不带第二个参数 `true` 只是暂存**（只改 activePosition.row），而 RDG 自己的 Enter/blur 处理用的是旧闭包 row → 暂存值丢失。必须 `onRowChange(row, true)`（内部 flushSync 同步 updateRow→onRowsChange）。
3. **gutter 列 `frozen: 'start'` 会导致该列被渲染两次**（React duplicate key `__gutter` 警告 + 行内单元格错位）。去掉 frozen 解决。
4. 自写 `DraftTextEditor`（本地 draft 状态，Enter/Tab/blur 才 `onRowChange(..., true)` 提交），避免 RDG 内置编辑器每键触发 onRowsChange 造成每键重写围栏。内置 `renderTextEditor` 是受控 input + 每键 onRowChange，不适合直接接外部持久化。

## 换类型失效：两个叠加根因（Playwright 实测定位）

用户报「更换类型弄不了」。写临时 Playwright spec 复现，抓到两个叠加 bug：

1. **Radix Portal 的点击沿 React 树冒泡回 RDG 表头**：PopoverContent 虽然传送到 body，但 React 合成事件按组件树冒泡——列菜单里的每次点击都会触发 RDG 表头自己的 click-to-sort → `onSortColumnsChange([])` → `clearSort()` 用**旧 data 闭包**整块重写，把刚提交的类型覆盖回 text。修法：新建 `view-table/popoverEventIsolation.ts` 导出 `isolatePopoverEvents`（onClick/onDoubleClick/onMouseDown/onPointerDown 全部 stopPropagation），铺在列菜单根 div、行菜单 content、select/multiSelect 单元格 PopoverContent 上。注意不要 preventDefault/stop native，焦点与 Radix outside-click 不受影响。
2. **空 source 的默认表列 id 不稳定**：新块 source=''，`parseViewTableData('')` 每次调 `defaultViewTableData()` 用全局 `columnIdCounter` 生成全新 id（UI useMemo 记住 c1-c3，commit 重 parse 得到 c7-c9）→ 第一次编辑按 c1 找列永远 miss，静默 no-op。修法：`defaultViewTableData()` 改为**固定 id**（name/status/notes），count 只留给用户加列（taken 去重）。

配套重构（ViewTableBlock.tsx）：`commit` 改为接收 **updater 函数** `(current) => next`，内部从 `sourceRef.current`（ref 同步 props + commit 自身也推进 ref，effect 里同步避免 react-hooks/refs 报错）重新 parse，彻底消灭「旧闭包整块覆盖」这类 bug；actions 只依赖 `[commit]`，不再随 data 重建。副作用修复：工具条改名/筛选在快速连续操作下也不会丢更新。

**验证（全绿）**：Playwright 实测 Text→Number→Checkbox→Text 连续切换 + 改名 Amount 全部生效、菜单内 active 高亮正确；数据层 esbuild bundle 自检 8 项通过（id 确定性、往返、换类型持久化、cell 写入、类型强转回 text、serialize∘parse 幂等）。tsc/eslint 全绿。临时 spec 已删。

### 关键坑：RDG 单元格里 Radix Popover 秒开秒关
图片/附件单元格的弹窗点开后立刻被 Radix 关掉：**focusOutside**。时序 = Radix onOpenAutoFocus 聚焦弹窗 → RDG 把焦点还给 cell → Radix 判定焦点离开弹窗 → dismiss（select chip 弹窗侥幸没触发同一路径）。修法：media 两个 PopoverContent 上 `onFocusOutside={(e) => e.preventDefault()}`（外点/Escape 仍会关闭）。**教训：在 RDG 单元格里放 Popover，默认要防 focusOutside 误关。**
