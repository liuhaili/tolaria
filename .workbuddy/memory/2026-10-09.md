## 侧栏树与图标改用存储文件管理（ADR 0188）

**背景**：用户提出左侧树结构与图标应改由一个存储文件管理，理由是「非 .md 文件无法把元数据存进文件内」。

**关键勘察结论**：
- 侧栏有**两棵树**：文件夹树（文件系统目录驱动，`FolderTree.tsx` / `FolderTreeRow.tsx`）与逻辑树（`NoteTree.tsx` + `src/utils/noteTree.ts`，由每篇笔记 frontmatter 的 `_parent_note` 驱动）。
- 图标同理走 frontmatter `_icon`（ADR 0049）；非 md（`fileKind: text | binary`）拿不到，降级为 `File` / `FileDashed`（`NoteItem.tsx:423`），树里一律 `FileText`（`VaultTreeEntryRow.tsx:33`）。
- **具体受害者**：ADR 0186 已记录 `.drawio`（XML，不能塞 frontmatter）被迫卡在树根。
- ADR 0184 已预留 `{vault}/tolaria/config/` 存放此类元数据，但**尚无代码写入**。
- 排除规则 `attachments | tolaria | views` **硬编码在 2 处**：`FolderTreeRow.tsx:360`、`NoteTree.tsx:22`。
- `views/` 仍在 vault 根（`vault/views.rs:195` 硬编码），未随 attachments 迁入 `tolaria/`；根级 `config/agents.md` 是已迁移的 legacy 位置（`config_seed.rs:363`）。
- 前端无 YAML 解析库，`serde_yaml 0.9` 在 Rust 侧已有；views 即由 Rust 解析后回传 —— tree.yml 沿用同一路线。

**决策（用户确认：存文件树结构和文件的图标）**：
- 新增 `{vault}/tolaria/config/tree.yml`，以 vault 相对路径为 key，存 `parent` / `order` / `icon`。
- 文件系统仍是「哪些条目存在」的唯一真源（ADR 0002）；tree.yml 只管呈现。
- 回退顺序：tree.yml → frontmatter（`_parent_note` / `_icon`，仅 md）→ 内置默认。停止写 `_parent_note`，但保留读取，零迁移、可回退。
- 新增 ADR `0188-vault-tree-structure-in-tolaria-config.md`，**废止 ADR 0185**；README 索引已补 0185（superseded）与 0188（active）。
- 代价：树不再随单个文件可移植（换 vault 丢位置与图标）；tree.yml 成为单一冲突点。已在 ADR 里记录触发重评条件。

**遗留待办（任务 #2–#5）**：Rust 侧 tree.rs 读写与剪枝、前端 vaultTree 纯解析器、抽出重复的托管路径常量、拖拽与重命名的 key 同步（挂在既有 rename 事务 ADR 0075 上）。

**流程约束提醒**：AGENTS.md 要求先立 Todoist/Linear 任务、TDD 先写失败用例、CodeScene 前后打分、`git push origin main` 才算完成；本次改动涉及新 UI 文案时需走 `pnpm l10n:translate`。Todoist 连接器当前不可用，任务暂记在会话任务列表。

## SheetBlock 拖拽时网格不跟着变大（根因 + 修复）
- 根因：IronCalc 只在自身渲染时按容器 clientWidth/clientHeight 设定 canvas 尺寸（Xv.setContext 写死 canvas width/height/style），
  且它只在 browser window resize 时重渲染（内部 oC() 用 window.innerHeight-190 设 model 窗口）。
  块自身变大不会触发重测量 → canvas 保持旧尺寸，下方留白、行数不变。
- 修法：SheetEditor 新增可选 viewportSize prop；SheetWorkbookSurface 在 render 期间做 state 调整（React 官方模式）比较尺寸，
  变化时 gridMeasureEpoch+1，传给 MemoizedIronCalc 的 refreshId = workbook.refreshId + gridMeasureEpoch → 重渲染 → 重新测量。
- SheetBlock 传 viewportSize={width,height}（useMemo），拖拽时实时生效；整篇 sheet 不传，行为不变。
- 文件：SheetEditor.tsx / SheetBlock.tsx / ADR 0192。tsc 通过。

- **生态里最标准的范式 = Obsidian Bases（内置核心插件）**：双形态 —— 独立 `.base` 文件（`![[File.base]]` 嵌入，可复用）或笔记内直接写 ` ```base ` 内联块（自包含、跟着 md 走）；声明式 YAML：filters(and/or/not) / views(table·cards·list·map) / order / sort / groupBy / summaries / formulas，属性即 frontmatter，**表格内可直接改属性写回**。1.10 公开版（2025-11）加入 group by、表格摘要、list 视图、初版 Bases API；社区已用它做 Kanban / Calendar companion views。
- 其他：Dataview（` ```dataview `，只读，DQL/JS 语法把用户锁死）、DB Folder（react-table 可编辑 Notion 式，已被 Bases 取代）、思源数据库块、AFFiNE BlockSuite database block、Logseq DB 版。
- **都不能直接用于 Tolaria**：它们是宿主插件（Obsidian plugin API / 各家后端 / 自家编辑器框架），Tolaria 是 BlockNote + Tauri，只可借鉴语法与交互约定，不可搬代码。
- **Tolaria 已有一半**：ADR 0144（Collection = 选中笔记集 + presentation 配置）+ `src/collections/`（presentationConfig / resolveCollectionEntries / collectionFromSelection）、`views/*.yml` 已支持 filters/sort/listPropertiesDisplay/order。缺口是：只有 `list` 一种呈现，且集合入口只在侧栏，**没有笔记内联块**。
- 建议落地（若用户要）：照 sheetBlock 五处接线做 `viewBlock`（围栏 ` ```view `/` ```database `），payload 只存「引用 views/x.yml + 可选覆盖」，数据仍来自 frontmatter（符合 ADR 0002/0144：presentation 只映射属性、不得自建数据存储）；呈现先 table（TanStack Table / glide-data-grid 等 headless）后 board（dnd-kit）；社区插件 API 等两个 presentation 落地后再谈（0144 明文）。

## 内联数据表：修「不能编辑」+ 补过滤/排序
用户反馈：列不能编辑、新增行不能编辑、过滤没有、排序没有。
- **根因（不能编辑）**：块内是真表单控件，但之前的防护用 React 的 `onMouseDown/onKeyDown stopPropagation` —— **无效**。
  React 17+ 事件委托挂在 app root，而 ProseMirror 的 `mousedown` 监听挂在编辑器元素上（root 的**后代**），冒泡时先于 root 触发；
  `prosemirror-view` 的 `handlers.mousedown` 会 `posAtCoords` → `MouseDown` → 重设选区并重聚焦编辑器
  → 输入框一点就失焦（onBlur 立刻提交并退出编辑态）、Radix popover 被 focus-outside 关掉。
- **修法**：`ViewTableBlock` 新增 `useIsolatedBlockEvents` —— 在**块根**用**原生冒泡**监听器拦
  `mousedown/mouseup/dblclick/contextmenu/dragstart/dragend/beforeinput/paste/copy/cut/keydown/keypress/keyup/touchstart/touchmove`
  并 `stopPropagation()`（**不 preventDefault**，否则 input 无法聚焦）。块根在编辑器元素**内部**，所以先于 ProseMirror 执行。
  故意不拦 `click`/`pointerdown`/`pointerup`/`input`/`focus*`：Radix popover（pointerdown+click）、复选框、列宽手柄（pointerdown）、React onChange（input）都靠它们。
  代价：块内 React **冒泡阶段** handler 对上述事件失效 → `TitleInput`/`TextCellEditor`/`DateCellEditor` 的 `onKeyDown` 改成 `onKeyDownCapture`；
  Popover 内控件不受影响（portal 在块外）。
- **排序**：模型加 `sort:{columnId,direction}`；列菜单加 升序/降序/清除（带 `data-active`），表头显示 ↑/↓，工具条显示可清除的排序 chip。
- **筛选**：模型加 `filters:[{id,columnId,op,value}]`（AND）+ 按列类型的 op 白名单（`viewTableFilterOps`）；工具条「筛选」popover 可加/改/删条件，带计数徽标。
  值输入按列类型给 text/number/date；value 为空视为不生效（否则输一半就隐藏全部行）。改列类型会重设该列不可表达的 op；删列会清掉相关 filter/sort。
- **统一行解析**：`viewTableVisibleRows(data, search)` = 过滤 → 搜索 → 排序，返回 `{row, index}`（index = 原始行号，保证 `changeCell(rowIndex)` 落到正确的行）；
  排序稳定（原始序号 tie-break），**空值恒排最后**（双向都是）；number 走数值比较，checkbox 走 false<true，其余 `localeCompare(numeric)`。
- 文件：viewTableModel.ts（新增 filter/sort 类型·规范化·序列化·`viewTableVisibleRows`·`addViewTableFilter`/`updateViewTableFilter`/`removeViewTableFilter`/`setViewTableSort`）、
  ViewTableBlock.tsx（事件隔离 + 接线）、view-table/{ViewTableGrid,ViewTableCell,ViewTableColumnMenu,ViewTableToolbar}、ViewTableBlock.css、locales en+zh-CN（+27 键）、ADR 0193。
- 校验：`npx tsc` exit 0、eslint 全绿、数据层纯函数自检脚本 18/18 通过（往返/旧围栏兼容/过滤/排序/空值下沉/数值排序/删列清理/搜索），脚本已删。
